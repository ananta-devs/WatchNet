# WatchNet Database Analysis

**Document Version:** 1.0.0  
**Baseline Snapshot:** `D:\WatchNet-Reference-Snapshot` (`server/db/schema/app.sql`, `server/db/db_upgrade.py`)  
**Target Platform:** WatchNet PostgreSQL 16 Architecture  

---

## 1. Upstream Database Schema & Organization

Legacy Upstream relies on a single embedded SQLite database (`app.db`). Schema definitions are declared in `app.sql` and dynamically altered at runtime through Python helper scripts (`db_upgrade.py`).

### 1.1 Complete Table Inventory
1. **`Devices`**: Central registry of all discovered network devices. Key columns: `devMac` (PRIMARY KEY), `devIp`, `devName`, `devVendor`, `devType`, `devStatus`, `devFirstConnection`, `devLastConnection`, `devAlert`, `devArchived`.
2. **`Events`**: Discrete transition events (new device, connected, disconnected, IP change). Key columns: `eveId`, `eveMac`, `eveIp`, `eveDateTime`, `eveEventType`, `eveAdditionalInfo`, `evePendingAlertEmail`.
3. **`Sessions`**: Continuous connection duration intervals. Key columns: `sesId`, `sesMac`, `sesIp`, `sesDateTimeConnection`, `sesDateTimeDisconnection`, `sesStillConnected`.
4. **`CurrentScan`**: Ephemeral staging table holding raw host sightings during an active scan execution. Key columns: `scanMac`, `scanIp`, `scanVendor`, `scanType`, `scanDateTime`.
5. **`Online_History`**: Presence bitmap aggregations for dashboard activity grids.
6. **`Resource_History`**: Host performance metrics (CPU, RAM, Disk, Temperature) recorded chronologically.
7. **`Settings`**: Key-value system configurations and user credentials (`setKey`, `setValue`, `setType`).
8. **`Parameters`**: Internal execution state flags and timestamps (`paramKey`, `paramValue`).
9. **`Plugins_Objects`**: Unstructured key-value store where plugins persist arbitrary JSON blobs.
10. **`Plugins_Events`**: Activity and status events generated by individual plugin executions.
11. **`Plugins_History`**: Audit records of plugin run timestamps, execution duration, and exit codes.
12. **`Plugins_Language_Strings`**: Internal UI localization strings cached in SQLite.
13. **`AppEvents`**: System runtime log messages and internal error reports.
14. **`Notifications`**: Outbound notification queue holding unsent push/email alerts.

## 2. SQLite Bottlenecks & Failure Modes

- **Write Locking**: SQLite's table-level and file-level locking mechanism locks the whole database when processing a large ARP scan batch, resulting in UI lockups and timeout errors in Flask API routes.
- **Lack of Foreign Key Constraints**: Upstream schemas omit strict relational constraints and cascading deletes, leading to orphaned events and sessions when devices are deleted.
- **Unstructured Metadata**: Plugin results stored as unindexed raw strings require regex and string manipulations inside application code.

---

## 3. WatchNet PostgreSQL Modernization

WatchNet migrates persistence to PostgreSQL 16:
- Fully relational schema managed by Alembic migrations with explicit foreign keys and check constraints.
- Multi-tenancy achieved natively via PostgreSQL Row-Level Security (RLS) on `tenant_id`.
- Native `JSONB` with GIN indexing for plugin-specific telemetry, metadata, and dynamic properties.
- Range-based partitioning on `events` and `presence_history` to allow zero-downtime historical data pruning.
